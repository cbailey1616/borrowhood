## Fixes

- Content reports were inserted on every submission. A durable per-account/content receipt now prevents duplicates inside the same database transaction as the report. Historical reports are retained and backfilled. The app checks the receipt and shows a disabled “Report submitted” action, including after reopening a post or moderation review. Different accounts can still report the same content.
- The feed snapshot used JavaScript time and millisecond precision. A committed post could fall beyond the cutoff. Snapshot creation and persistence now use PostgreSQL time and microsecond precision.
- The native SVG image decoder rendered the QR background's percentage dimensions as a small white patch. Explicit dimensions preserve the full white quiet zone.

## Limits and release order

Deploy the server migration and report-status endpoint before releasing the new mobile client. These changes have not been deployed or submitted to the App Store.

Native interaction checks used build 293 JavaScript with an existing build 216 development client on iPhone 17 Pro / iOS 26.5. They are not validation of the signed build 293 binary. The old client lacks the newer `borrowhood://` registration; the supported `com.borrowhood.app://` profile path worked. Fresh native build, universal links from Camera, physical-device Apple/Google sign-in, push permissions, and payment/provider flows remain release gates. Tests use isolated synthetic accounts and block outbound server calls.

Duo work is being prepared separately on `qa/duo-sdk58-20261023`. The local Xcode 26.6 installation has no iPhone Duo runtime. Full Duo certification requires Xcode 27.1 and real fold/resize, keyboard, safe-area, biometric, and warm/cold link checks. No claim that every screen or physical device has passed.
