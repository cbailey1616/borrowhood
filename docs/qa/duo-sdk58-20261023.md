# Adaptive iOS preview — 2026-10-23

This branch builds on the launch fixes in PR #83. It prepares Borrowhood for the iPhone Duo window lifecycle and tests the same responsive interface on existing phones and iPads. It is not a release certification.

## Changes

- Upgrade Expo to 58.0.17, React Native to 0.88.0, and React to 19.3.0; regenerate the iOS native project and dependencies. The minimum supported iOS version becomes 16.4.
- Create the native window through Expo's scene delegate. Support both orientations and dynamically size content from the current window, with parchment behind the full window.
- Keep navigation along the bottom in compact and wide windows. Tab scenes use the entire window width with no side-rail reservation. Preserve the navigator and selected tab while the layout changes; use the current content width for grids, artwork, and safe-area padding.
- Make headers, modal controls, action sheets, and bottom navigation respect horizontal safe areas. Keep Profile readable on wide windows while the background fills the display.
- Replace removed InteractionManager calls with cancellable idle work.
- Migrate My items and saved-plan swipe rows to Gesture Handler 3's ReanimatedSwipeable. The old named export was undefined at runtime and crashed those screens; mocks now use the actual entry point.

## Current responsive layout and ribbon follow-up

- Home, Ideas, My items, Inbox, and Profile use the full current window. Body content no longer reserves the Duo status strip or a 660-point feed column. Wide windows use item/idea grids, grouped Profile settings, and a wider chat split view; narrow windows stack naturally. Bottom-navigation measurements determine scrolling clearance.
- My items uses two or three columns in wide windows. Swipe actions are clipped to the row and remain invisible until dragging; card spacing lives outside the swipe surface.
- Shared secondary routes use centered readable content, while the parchment fills the window. Forms retain their component identity when resizing.
- Landscape artwork measures its own header bounds, keeps the original geometry, and crops rather than stretching to fit. The main headings overlap a compact landscape; the smaller tabs and search controls sit below the artwork on parchment. The landscape now fills the space already required by the corner status UI, ending eight points above its lower edge. This extends the scene approximately 54 points farther down on a folded Duo while preserving the title and content positions; the smaller labels remain below the scene.
- A native iOS 27.1 view reads UIKit occlusion regions. Only the heading row crossing the system clock/camera area reserves horizontal space; lower controls clear the region vertically and retain the full width. Other platforms and older iOS versions use safe-area fallbacks. The native bridge is preserved through Expo prebuild by `plugins/withReservedRegions.js` and its canonical Objective-C source.
- The simulator preview now uses Xcode's simulated signing entitlements, which allow SecureStore sign-in. The QA-only IPv6 loopback proxy forwards localhost traffic to the synthetic test API. Neither is a production networking change.
