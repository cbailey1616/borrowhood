# Build 217: alpha checklist

Use TestFlight build **217**. For the Town identity check, use two accounts in the same town that are not already friends or sharing a neighborhood; existing connections retain their normal permissions.

- [ ] **Neighborhood selection:** Start an item or request, choose Neighborhood, and try Join, Create and Not now. Returning should preserve the draft.
- [ ] **Popups:** Open and close menus several times. Every popup should be visible and the underlying screen should work after dismissal.
- [ ] **Town browsing:** An unverified account can preview eligible Town posts with “Identity hidden · Get verified.” A verified account can see the poster. Tapping the prompt opens verification.
- [ ] **Sharing privacy:** Test a newly saved Town post and an Only me item. Private inventory stays private. Older Town posts need their sharing selection saved again to enable previews.
- [ ] **Request creation:** The large explanatory cards are gone. Audience selection offers useful invite, neighborhood or verification actions when needed.
- [ ] **Profile controls:** Open another tester’s More menu. Check Report options without submitting a real report, then Block and Unblock. Blocking stops new DMs both ways; previous conversations and borrows remain accessible.
- [ ] **Notifications:** Change settings, leave and return. Preferences stay saved. Messages appear in Messages without duplicate Activity alerts. Borrow updates and post replies still open the relevant details.
- [ ] **Fee switch:** The off state is visible on parchment. Enable a fee, save a price and reopen the listing. Payment is arranged directly between the parties.
- [ ] **Onboarding:** Get verified and Explore first lead somewhere clear, and Town browsing remains available without verification.

For any issue, send the screen name, the steps immediately before it happened, the expected result, the actual result, and a screenshot or recording. Include whether the account was verified and its selected sharing audience.
