# Android QA and internal testing preparation — October 24, 2026

## Result

Android and iOS regression runs each passed **173 suites / 1,714 tests**. All 73 screen source files now have a dedicated test file; this is component coverage, not a claim that all live flows have been exercised on Android.

The navigation source audit traversed 225 modules, found 69 registered routes, 202 navigation calls and 481 pressable controls, and reported no missing static destinations or required parameters. Thirteen dynamic destinations require runtime/context review; the static audit cannot prove those.

## Layering follow-up

The Android screenshot exposed an additional SDK migration issue: React Native 0.88 removed `StyleSheet.absoluteFillObject`. Its undefined value silently removed fullscreen geometry from dimming layers, photo overlays and the email-code input. Replaced all 12 references across eight source files with supported `StyleSheet.absoluteFill`. Added geometry and outside-tap dismissal regressions for rank and action sheets. The native rank-sheet screenshot now shows a dimmed underlying Profile and a clear cream foreground panel. Both platform suites pass 1,714 tests after this change.

## Fixes

- Enabled the Borrowhood spinning hat for Android refresh lists and keyboard-aware Ideas pages. Android does not provide negative overscroll offsets, so refreshing reserves an 80-point gap and holds the hat for the existing animation duration.
- Moved Android's native refresh indicator outside the viewport so only the hat is shown. The native pull gesture remains active. Verified with a real emulator swipe and screenshot after release.
- Reduced the Android splash image width from 200 to 140 points so the feather fits Android's circular launch mask. iOS keeps its existing width. Native build validation is tracked below.
- Fixed the emulator launcher to bind Metro on a host reachable through Android's IPv4 ADB reverse connection.
- Made artwork decoding, native Switch state, mock crop controls, and date-picker assertions platform aware. Explicitly Apple-only and iOS geometry fixtures select iOS; Android-specific behavior remains separately exercised.
- Added Android regression tests to the Android checks workflow.
- Added dedicated tests for Privacy & safety actions and mail-app fallback, circle details/invitation choices/load recovery, and the Ideas wrapper.

## Native checks

Observed read-only navigation in the signed-in Android emulator: Home, Ideas, My items, Inbox, Profile, Edit Profile, My Neighborhood, Past exchanges, Your exchanges, Friends, Notification Settings, Privacy & safety and its sharing accordion. Existing prior visual checks also cover project illustrations, tabs, badges and ribbons. Opening a screen is narrower evidence than submitting its forms.

No messages, invitations, posts, exchanges, reports, account changes, or purchases were submitted as part of these native checks. Submit/error/retry behavior is tested with mocked services; that does not substitute for a controlled two-account backend/device test.

Local native screenshots are under mobile/.maestro/screenshots/android-audit/ and are deliberately not committed with account content.
